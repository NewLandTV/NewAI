# NewAI 문맥 생성·음성 실험 보고서

**결론:** 새 답변을 만들고 최근 대화를 반영하는 기능은 확인했습니다. 한국어 공감과 설명은 아직 일관되지 않고, 이 실험의 CPU 응답 시간은 실시간 대화에 적합하지 않았습니다. 그래서 검수된 답의 일관성이 중요한 기존 `daily`를 기본으로 두고, 자유 생성 모델 `context`와 음성을 선택 기능으로 제공해요. [실행·다운로드 안내](../README.md#새-문맥음성-모드-실행)를 참고하세요.

## 무엇을 어떻게 왜 바꿨나요?

| 문제 | 변경 | 선정 이유와 한계 |
| --- | --- | --- |
| 검색형 `daily`가 고정 답 중 하나를 고르고 앞 대화를 보지 못함 | Qwen3-1.7B Q4_K_M으로 답을 생성하고 최근 문답 최대 3쌍을 함께 전달 | 로컬 CPU에서 실행 가능한 크기이며, 이름·수정 내용·창작 요청에 직접 답할 수 있음. 길거나 오래된 맥락은 잘리고 답변 검증은 따로 필요 |
| 같은 보류 문장이 반복됨 | 모호하면 무엇이 빠졌는지 묻고, 실시간 시세·날씨를 조회해야 하는 일부 질문은 확인할 곳을 알려 줌 | 보류 자체를 없애는 대신 다시 물어봐야 할 이유를 구체화. 알레르기 맥락을 감지한 일부 음식 질문에는 메뉴가 안전하다고 장담하지 않음. 패턴 밖 질문과 오답을 모두 잡는 것은 아님 |
| 감정 표현과 설명이 빈약함 | 검수 대화에 공감·창작·수정·설명 예를 넣고, 추론 시 짧은 공개 근거를 요청 | 감정을 갖거나 인간처럼 사고한다는 뜻이 아님. 내부 추론을 출력하는 대신 답을 이해하는 데 필요한 이유를 짧게 말하도록 요청. 공감 학습 예시는 현재 배포 후보 Qwen3 가중치에 학습된 것이 아님 |
| 키보드로만 대화 가능 | Whisper로 한국어를 받아쓰고 Canora `seoyeon`으로 응답을 합성 | 한국어·로컬 실행·모델 라이선스·메모리 부담을 기준으로 선택. 한 가지 합성 스타일이라 감정 억양을 직접 제어하거나 실시간 음성 변조를 하지는 않음 |

## 훈련: 처음부터 만드는 경로와 사전학습 모델을 쓰는 경로

[Vaswani 외, *Attention Is All You Need* (2017)](https://arxiv.org/abs/1706.03762)의 자기 어텐션을 바탕으로 한 **디코더 전용, 다음 토큰 예측** 구조를 사용합니다. 원 논문의 번역용 인코더–디코더를 그대로 구현한 것은 아니에요. 새로 초기화하는 경로는 바이트 단위 BPE와 Qwen2 계열 디코더를 사용합니다. 일반 문서로 사전학습하고, 대화로 미세조정할 때는 마지막 어시스턴트 답변에만 손실을 계산합니다. 사용자 말과 앞 대화는 맞혀야 할 답이 아니라 답을 만들기 위한 맥락이에요.

- 대화는 [UA-N1-Queen `5a65364`](https://github.com/NewLandTV/UA-N1-Queen/tree/5a653644a2452583a16a29d766e01e1d20a5d180) (Apache 2.0), [Song 일상 데이터 `4cf20d1`](https://github.com/songys/Chatbot_data/tree/4cf20d13fc46f5037fd1c531cd566e2dd9f72974) (MIT)를 [정제](daily-model.md)한 파일과 직접 작성한 문맥 대화 10개를 씁니다. 정규화한 동일 질문은 같은 분할에 유지하고, 문맥 평가의 질문 및 사용자 문장과 정확히 겹치는 예는 대화 학습에서 제외합니다. 유사 문장이나 외부 사전학습과의 겹침까지 제거한 것은 아닙니다.
- **처음부터 학습한 검증:** 합성 문서로 사전학습한 448,768개 파라미터 모델을 이어받아 대화 미세조정까지 완료했습니다. 처리된 학습/검증/테스트 예는 사전학습 `48/12/12`, 대화 미세조정 `51/12/12`였고 각 테스트 손실은 `5.625`, `5.930`이었어요. 서로 다른 데이터와 목표라 두 값을 직접 비교할 수 없고, 이 테스트의 목적은 학습·저장·이어받기 검증입니다.
- **LoRA 검증:** [Hu 외, *LoRA*](https://arxiv.org/abs/2106.09685)에 따라 Qwen2.5-0.5B의 가중치를 고정하고 쿼리·값 투영에 저랭크 가중치를 넣는 경로를 추가했습니다. 이 환경의 FP32 시도는 메모리 한계로 종료 코드 137로 끝났고, BF16·체크포인팅으로 줄인 시도도 느려 완료 전에 중단했습니다. 사용할 수 있는 어댑터나 개선 점수는 없습니다.
- **실행 후보는 외부 사전학습 모델:** [Qwen3-1.7B](https://huggingface.co/Qwen/Qwen3-1.7B)의 양자화판이지 NewAI가 17억 파라미터를 처음부터 학습한 결과가 아닙니다. [GPT-2](https://cdn.openai.com/better-language-models/language_models_are_unsupervised_multitask_learners.pdf)의 가장 큰 모델은 약 15억 파라미터, [GPT-3 논문](https://arxiv.org/html/2005.14165v2)의 가장 큰 모델은 1,750억 파라미터예요. 비슷한 파라미터 수가 같은 품질을 뜻하지 않습니다. 현재 평가는 GPT-2~GPT-3 수준을 검증하지 않았습니다.

### 재현

Python 가상 환경을 활성화하고 설치·다운로드한 뒤 실행하세요. 이미 존재하는 결과 폴더나 합성 문서 파일은 덮어쓰지 않아요.

```sh
python -m pip install -r model/requirements-context.txt
python model/fetch_dataset.py
python model/prepare_daily.py
python model/make_smoke_corpus.py dataset/pretrain-smoke.jsonl
python model/train_context.py --mode scratch --pretrain dataset/pretrain-smoke.jsonl --out checkpoints/context-pretrain-smoke --cpu --epochs 1 --limit-train 48 --limit-eval 12 --batch 4
python model/train_context.py --mode scratch --init checkpoints/context-pretrain-smoke/best --out checkpoints/context-transfer-smoke --cpu --epochs 1 --context 384 --limit-train 48 --limit-eval 12 --batch 4
```

실제 사전학습은 권리를 검토한 `{"text":"문서 본문"}` 형식의 JSONL을 별도로 준비하세요. 기본 실행은 작은 `smoke` 모델이며, `--size 124m`·`350m`은 더 큰 구조를 지정할 뿐 실측 결과가 아닙니다. 실제 크기는 토큰 사전에 따라 달라집니다. 다음 단계에서는 출처·허용 범위를 기록한 한국어 문서를 늘리고, 문서 단위 중복 제거와 개인정보 검수, 주제별 고정 평가를 먼저 마련하는 것이 좋아요. 권리가 확인되지 않은 디스코드 대화·음성은 학습에 넣지 않습니다.

메모리가 충분한 환경에서만 선택적으로 `python model/fetch_runtime.py qwen` 후 `python model/train_context.py --mode lora --out checkpoints/context-lora --epochs 2`를 실행하세요. 성공할 경우 `evaluate_context.py --adapter checkpoints/context-lora/best`로 같은 문항을 평가할 수 있어요. 어댑터는 `research` 실행 경로의 Qwen2.5 계열 실험용이며, Qwen3 GGUF 모드에는 적용되지 않습니다.

## 같은 질문으로 평가

`model/context_eval.json`의 직접 작성한 8개 질문과 판정 기준을 세 후보에 동일하게 적용했습니다. `daily`는 기존과 같이 마지막 질문만 보고, 생성형 두 후보는 해당 문항에 명시된 앞 대화도 받습니다. Qwen2.5는 탐욕 디코딩, Qwen3는 문항별 시드 `42`부터 `49`까지로 샘플링했습니다. 아래는 고정 가중치와 기본 설정으로 실행한 결과의 발췌·요약이며, 반복 평가나 블라인드 채점은 아닙니다.

| 문항 | 기존 `daily` | Qwen2.5-0.5B | 새 `context` (Qwen3-1.7B) |
| --- | --- | --- | --- |
| 화분 이름 기억 | 봇의 자기소개 | “당신의 화분 이름은 ‘초롱’이라고 했습니다.” | **충족** — “화분 이름은 초롱이에요!” |
| 달걀 알레르기, 따뜻한 점심 두 가지 | 김밥·샌드위치·국수·덮밥, 알레르기 미반영 | 달걀을 넣은 짜장면·국수 제안 — 제약 위반 | **부분** — 교차 접촉과 재료 확인을 안내. 안전한 메뉴라고 지어내지 않았지만 두 가지 점심을 제안하지는 못함(규칙) |
| 영화가 토요일에서 일요일로 변경 | 공통 보류 | 영화 날짜를 다시 물음 | **충족** — “일요일에 영화를 보는 건 어때요.” 최신 요일은 맞지만 확인형 답변이 더 자연스러움 |
| 말을 더듬어 창피함 | 공통 보류 | “그런 행동은 좋지 않습니다” | **미충족** — 창피함은 짚었으나 “내면에서는 계속 놀라움과 실망감”을 단정하고 어색한 조언을 함 |
| 달의 빵집 이름 세 개 | 공통 보류 | ‘달빛 빵집’, ‘밤새 빵집’, ‘흰색 빵집’ | **부분** — ‘달밀빵’을 만들었지만 두 번째 항목 앞에서 끊김. 초기 실행에서는 세 이름을 냈고, 한 번의 성공으로 안정적인 생성이라 볼 수 없음 |
| 비가 올 때 기다릴 이유 | 공통 보류 | 우산과 물건 보관을 설명 | **부분** — 비가 잦아들 가능성을 언급했지만 “흐르는 물을 걷는” 등 엉뚱한 설명을 섞음 |
| “그거 준비해 줘요.” | 공통 보류 | 어떤 도움이 필요한지 일반적으로 질문 | **부분** — “지금은 어떤 것인가요?”라고 대상을 묻지만 “물어보기 힘들다”라는 불필요한 서두를 붙임 |
| 실시간 환율 | 공통 보류 | 조회 불가와 확인 방법 (규칙) | **충족** — 수치를 지어내지 않고 은행·거래소의 최신 시세로 안내(규칙) |

- 기존 보류 문장 “지금은 그 질문에 맞는 답을 자신 있게 고르기 어려워요…”는 이 문항에서 **`daily` 6/8, `context` 0/8**이었어요. 새 모드가 답을 더 자주 시도한다는 뜻이지 더 자주 정확하다는 뜻은 아닙니다. `context`가 기준을 전부 충족한 건 위 판정에서 **3/8**이며 하나는 규칙 처리였어요. 범위 밖 최신 정보와 중요한 제약은 무조건 그럴듯한 답을 하는 대신 좁혀 묻거나 확인을 안내하는 편이 낫습니다.
- 2 vCPU Intel Xeon 샌드박스에서 모델 로딩을 제외한 문항별 응답을 측정했습니다. `daily`는 이 8개에서 1ms 미만, Qwen2.5의 실제 생성은 약 1.9~11.3초, Qwen3의 실제 생성은 약 **4.7~15.2초**였어요. 규칙 처리 2개는 Qwen3에서 1ms 미만이라 생성 범위에서 뺐습니다. CPU를 다른 학습과 공유한 초기 실행은 훨씬 느렸어요. 기기와 생성 길이에 따라 달라집니다.

```sh
python model/evaluate_context.py --daily-only
node model/gguf-context.mjs evaluate
# 선택: 연구용 Python 의존성과 qwen 묶음을 설치한 뒤 Qwen2.5도 비교
python model/evaluate_context.py
```

## 음성 검증

설치 후 합성 음성으로 **TTS → Discord 형식 Opus 변환·디코딩 → STT → 이전 맥락을 읽어 답 생성 → TTS → 송출용 Opus 프레임**을 로컬에서 확인했습니다. 실제 디스코드 계정이나 참가자의 녹음은 사용하지 않았어요. 별도의 로컬 지연 측정은 아래 명령으로 재현할 수 있습니다.

```sh
python model/evaluate_speech.py
```

같은 2 vCPU에서 합성 문장 3개(각 2.7~3.0초)가 모두 원문 그대로 전사됐어요. 합성은 **3.7~4.0초**, 전사는 **0.95~1.03초**가 걸렸어요. 모델 로딩·답변 생성·네트워크를 뺀 수치입니다. 로컬에서 합성한 깨끗한 클립만 사용했으므로 사람 음성 인식률이나 자연스러움, 실시간 반응을 검증한 결과는 아니에요.

디스코드 음성 연결은 [Discord Voice Connections](https://docs.discord.com/developers/topics/voice-connections.md)와 DAVE를 지원하는 `@discordjs/voice`를 사용합니다. 로컬 패킷 테스트는 실제 서버의 접속·DAVE 협상·네트워크 왕복과 다릅니다. 응답 합성이 끝난 뒤 재생하므로 응답 도중 끼어들 수 없고, 긴 발화는 최대 12초까지만 받습니다. 종료하거나 5분간 새 발화가 없으면 나가고 음성 문맥을 지웁니다. 처리 중이던 발화가 있다면 그 답은 재생하지 않습니다.

실서버에서는 다음 순서로 확인해 주세요.

1. 동의한 사람만 있는 일반 음성 채널에서 `@NewAI 음성 시작 인사`를 보내고 합성 인사가 들리는지 확인합니다.
2. 인사가 끝나면 “제 화분 이름은 초롱이에요”라고 말하고, 답이 끝난 뒤 “화분 이름이 뭐였죠?”라고 다시 물어보세요. 다른 참가자만 말할 때는 봇이 응답하지 않아야 합니다.
3. `@NewAI 음성 종료` 또는 채널 이탈 후 다시 시작해 이전 이름을 기억하지 않는지 확인합니다. 시끄러운 환경과 다른 발화자, 실제 첫 소리까지 걸리는 시간은 별도로 검증해야 합니다.
